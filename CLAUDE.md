## What This Is

`tauri-plugin-nostr` is a Tauri 2.x plugin implementing encrypted, decentralized state sync across app instances using Nostr replaceable events (NIP-33, kind `30078`) as transport, with NIP-44 encryption. The full design spec is in `specs/tauri-plugin-nostr.md`.

The plugin is **transport only** — it moves encrypted blobs between instances via Nostr relays. Key derivation, storage, schema versioning, and conflict resolution are the host app's responsibility.

```

tauri-plugin-nostr/             # The plugin itself
  src/                          # Rust plugin core
    lib.rs                      # Plugin registration, TauriPluginNostrExt trait

    mobile.rs                   # Mobile platform implementation

  dist-js/                      # Built JS/TS output (generated by rollup)
  permissions/default.toml      # Tauri capability permissions
  build.rs                      # Registers commands with tauri-plugin build system
  Cargo.toml                    # Rust crate: tauri-plugin-nostr
  package.json                  # npm package: tauri-plugin-nostr-api
  rollup.config.js              # Bundles guest-js → dist-js
  tsconfig.json
  examples/tauri-app/           # Reference Svelte app consuming the plugin
    src-tauri/                  # Example app's Rust side
    src/                        # Example app's Svelte/JS side
```

## Architecture

### Dual-layer plugin structure

Every Tauri plugin has two layers that must stay in sync:

1. **Rust layer** (`src/`): Commands registered in `build.rs` and `lib.rs`, implemented in `desktop.rs` / `mobile.rs`. Each command added to `build.rs`'s `COMMANDS` array must have a corresponding `#[command]` fn in `commands.rs` and a `permissions/` entry.

2. **TypeScript layer** (`guest-js/index.ts`): Thin wrappers calling `invoke('plugin:tauri-plugin-nostr|<command>', ...)`. Built to `dist-js/` by rollup. The `dist-js/` files are checked in and consumed by apps.

### Platform split

`lib.rs` uses `#[cfg(desktop)]` / `#[cfg(mobile)]` to switch between `desktop.rs` and `mobile.rs`. Both expose a `TauriPluginNostr<R>` struct with the same methods. The mobile path delegates to the native layer via `PluginInvokeError`.

### Intended implementation (per spec)

The current scaffold only has a `ping` command. The spec defines the full API to build:

- `publish` / `fetch` / `syncAll` commands
- `addRelay` / `removeRelay` / `getRelays` / `getPubkey` / `getStatus`
- `NostrSyncState` with `relay_pool` (nostr-sdk), `outbox` (persisted JSONL retry queue), and `keypair`
- Keypair injected at runtime via `set_keypair` / `clear_keypair` (not at init)
- Events emitted to frontend: `nostr-sync://updated`, `nostr-sync://relay-status`, `nostr-sync://error`

### Key design constraints

- The keypair is **not** provided at builder time — it is injected after wallet unlock. Publish calls before keypair injection must queue to the outbox.
- Outbox stores already-encrypted NIP-44 ciphertext (never plaintext).
- 64KB hard payload limit enforced before any relay interaction.
- d-tag format: `{namespace}/{category}/v1`
- `syncAll()` is **not** called automatically on startup — the host app calls it explicitly.

## Testing Levels (from spec)

| Level | Command | Notes |
|---|---|---|
| 1 — Unit | `cargo test` | Pure logic, no I/O |
| 2 — Integration | `cargo test` (in `tests/`) | Mock relay via tokio |
| 3 — Tauri commands | `cargo test` with `tauri::test` | Uses `MockRuntime` |
| 4 — E2E | `cargo test --ignored` | Requires local relay, Docker |

CI runs levels 1–3. Level 4 tests are gated with `#[ignore = "requires local relay"]`.
