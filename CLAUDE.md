# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

`tauri-plugin-nostr-sync` is a Tauri 2.x plugin implementing encrypted, decentralized state sync across app instances using NIP-78 arbitrary custom app data events (kind `30078`, parameterized replaceable via NIP-33) as transport, with NIP-44 encryption. The full design spec is in `specs/tauri-plugin-nostr.md`.

The plugin is **transport only** — it moves encrypted blobs between instances via Nostr relays. Key derivation, storage, schema versioning, and conflict resolution are the host app's responsibility.

The crate is `tauri-plugin-nostr-sync` on crates.io and the JS bindings ship as `tauri-plugin-nostr-sync-api` on npm.

## Implementation Status

The plugin is being built in phases.

- **Phase 1 (shipped)**: in-process Rust state machine in `src/state.rs` (`NostrSyncState`). Signer lifecycle, relay add/remove, payload encrypt/decrypt, single-shot `publish` and `fetch`, namespace + d-tag construction, payload size guard. Unit + tokio tests in-line.
- **Phase 2 (shipped)**: 9 Tauri IPC commands (`publish`, `fetch`, `sync_all`, `add_relay`, `remove_relay`, `get_relays`, `get_pubkey`, `get_status`, `poll`), permission files, TypeScript bindings for all commands, configurable `PluginBuilder` (also exported as `Builder`) with `.relays()` / `.app_namespace()` / `.device_id()`, Level 2 mock-relay integration tests, Level 4 e2e test (gated `#[ignore]`). `poll()` emits `nostr-sync://updated` as a side effect. **Deferred to Phase 3**: `nostr-sync://relay-status` and `nostr-sync://error` frontend events. Outbox/retry has been removed from scope.

When extending the plugin, treat the spec (`specs/tauri-plugin-nostr.md`) and README as the contract. Do not invent new API shapes.

## Architecture

### Dual-layer plugin structure

Every Tauri plugin has two layers that must stay in sync:

1. **Rust layer** (`src/`): Commands registered in `build.rs` and `lib.rs`, implemented in `commands.rs` and delegated to `NostrSyncState` (via `desktop.rs` / `mobile.rs`). Each command added to `build.rs`'s `COMMANDS` array must have a corresponding `#[command]` fn in `commands.rs` and a matching `permissions/` entry.

2. **TypeScript layer** (`guest-js/index.ts`): Thin wrappers calling `invoke('plugin:tauri-plugin-nostr-sync|<command>', ...)`. Built to `dist-js/` by rollup. The `dist-js/` files are checked in and consumed by apps.

### Platform split

`lib.rs` uses `#[cfg(desktop)]` / `#[cfg(mobile)]` to switch between `desktop.rs` and `mobile.rs`. Both expose a `TauriPluginNostrSync<R>` struct. Desktop wraps an `Arc<NostrSyncState>` and delegates each method; mobile holds a `PluginHandle` and is currently a stub. The extension trait is `TauriPluginNostrSyncExt`, and host apps reach the plugin via `app.nostr_sync()`.

### State machine (`src/state.rs`)

`NostrSyncState` owns an `nostr_sdk::Client` plus a namespace and per-process `device_id` (UUID v4). Signer storage lives inside the `Client` itself — the plugin calls `client.set_signer` / `client.unset_signer` and never holds raw key bytes. `pubkey()` reads the signer's public key on demand.

`status().ready` is `true` only when a signer is set *and* at least one relay is `RelayStatus::Connected`.

`publish` builds an unsigned `EventBuilder` with kind `30078`, the d-tag identifier, and a `device_id` tag, NIP-44-encrypts the JSON payload, signs via the injected signer, and sends through the client. `fetch` runs a `Filter` for `(kind=30078, author=pubkey, d-tag)` with a 10s timeout and decrypts the first match.

Payload size is checked against a 64KB hard limit *before* encryption.

### Key design constraints

- The signer is **not** provided at builder time — it is injected after the host app unlocks keys via `app.nostr_sync().set_signer(...)`. Pre-injection publish calls return `Error::SignerNotSet`. There is no outbox.
- `set_signer` / `clear_signer` are Rust-only — there are no IPC equivalents. The frontend cannot manage the signer.
- The plugin holds signing capability through `nostr_sdk::NostrSigner`, not raw `SecretKey` bytes. `nostr_sdk::Keys` is `ZeroizeOnDrop`; do not clone the signer or its inner secret into unzeroized storage.
- 64KB hard payload limit enforced before any relay interaction.
- d-tag format: `{namespace}/{category}/v1`. Namespace must be non-empty and contain no `/`. Same constraint applies to category.
- `syncAll()` is **not** called automatically on startup — the host app calls it explicitly after signer injection.
- `poll()` deduplicates against an in-process `last_seen` map (per-category `Timestamp`). Only events newer than the last seen timestamp are returned. The map resets on process restart.
- `poll()` emits `nostr-sync://updated` for each new result as a side effect, so frontends can `listen` for updates.

## Testing Levels (from spec)

| Level | Command | Notes |
|---|---|---|
| 1 — Unit | `cargo test` | Pure logic + tokio runtime tests in `src/state.rs` |
| 2 — Integration | `cargo test` (in `tests/`) | Mock relay via tokio (shipped) |
| 3 — Tauri commands | n/a | Skipped — command handlers are trivially thin delegation; no logic to test |
| 4 — E2E | `cargo test --ignored` | Requires local relay (`docker run -p 7777:8080 scsibug/nostr-rs-relay`) |

CI runs levels 1–2. Level 4 tests are gated with `#[ignore = "requires local relay"]`.
